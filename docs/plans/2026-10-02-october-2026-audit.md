# October 2026 audit — security hardening, bug fixes, upstream ports

Status: implementing on `improvement/october-2026-audit`.

## Why

The 2026-10-02 project review found three groups of problems in v0.5.0:

1. **Security.** `wireviz-gui` sends YAML from a browser to `wireviz.parse()`.
   With that YAML a caller can read any local file into the SVG, inject
   script into the SVG and HTML output, read files through `parse()`'s
   str-as-path heuristic, and exhaust memory.
2. **Bugs.** 19 confirmed defects. Most sit at the seams between the
   v0.5.0 upstream ports (stdin/stdout, YAML-in-PNG, dpi, templates).
3. **Upkeep.** Click 8.5 broke two tests. CI still tests EOL Python
   3.7/3.8. `setup.py` has no dependency floors. One small upstream bug
   fix (#498) and one open upstream bug (#510) apply to us.

## Threat model

Two callers, two trust levels:

| Caller | Who writes the YAML | Trust |
|---|---|---|
| CLI, scripts, `build_examples.py` | The person who runs it | Trusted |
| `wireviz-gui` sidecar, any server | Anyone who can reach the endpoint | **Untrusted** |

Trusted callers legitimately use absolute image paths, `../` paths into
shared libraries, custom templates by path, `tweak:` and raw HTML in
labels. Hardening must not break them. So the design has two layers:

- **Always on.** Fixes with no legitimate use to lose.
- **Opt-in `untrusted=True`.** Restrictions that would break trusted use.

## Design

### Always on

| Change | Where | Finding |
|---|---|---|
| `embed_svg_images` inlines only the image files WireViz itself resolved from `image.src`. Any other `<image>` reference stays untouched. | `svgembed.py`, `Harness._render` | C1 |
| `options.fontname` must match `^[\w ,.'-]+$`. | `DataClasses.Options` | C1, C2 |
| `expand()` rejects non-scalar entries and ranges longer than `MAX_EXPAND` (10 000). `pincount` and `wirecount` are capped at the same value. | `wv_helper.py`, `DataClasses.py` | M1 |
| PNG YAML read and write work on raw PNG chunks. No pixel decode. | `Harness.py` | M2, bug 6 |
| `image.src` is XML-escaped in Graphviz HTML labels. | `wv_gv_html.py` | bug 16 |

### Opt-in: `parse(..., untrusted=True)`

The flag is stored on `Harness.untrusted`, so `Harness._render` (which
the sidecar calls directly) applies the output rules too.

| Rule | Finding |
|---|---|
| A `str` input is always YAML text. It is never read as a path. | H3 |
| Input larger than `UNTRUSTED_MAX_INPUT_BYTES` (1 MB) is rejected. | M1 |
| `image.src` must be relative and must resolve inside one of `image_paths`. | H2 |
| `metadata.template.name` must match `^[\w-]+$` and must resolve inside the search roots. | M3 |
| `tweak:` (global and per node) is rejected. Raw DOT cannot be made safe. | C2 |
| The SVG is parsed as XML and sanitized. `<script>`, `<foreignObject>`, `on*` attributes, `<image>` that is not a data URI, and links whose scheme is not http, https or mailto are removed. | C2 |
| HTML output: metadata values and BOM cells pass through an allowlist sanitizer (`a[href]`, `b`, `i`, `u`, `s`, `sub`, `sup`, `br`, `font[color]`, `span`). `fontname` is escaped. | H1 |
| Each Graphviz call has a timeout (`UNTRUSTED_RENDER_TIMEOUT`, 30 s). | M1 |

New module `wv_safety.py` holds the limits, the SVG sanitizer and the
HTML fragment sanitizer.

### `parse()` API changes

All changes keep existing callers working.

- `image_paths` default becomes `None`. The function never mutates the
  caller's list.
- `untrusted: bool = False` is new.
- `output_formats` and `return_types` accept a bare `str`.
- `source_path` adds its directory to the image search path for `str`
  and `dict` input.
- A `Path` input is always a path. A `UnicodeDecodeError` is raised, not
  swallowed.
- A dict input is serialized to YAML only when a PNG with an embedded
  YAML chunk is requested. If serialization fails, the PNG is written
  without the chunk and a warning goes to stderr.
- `parse()` returns a PNG with the embedded YAML chunk for
  `return_types="png"` too, so file, stdout and return outputs match.

### Upstream ports and upkeep

- #498 / #497: see bug 14.
- #282 (AWG table): **not changed.** The one table serves both
  directions. AWG → mm² rounds up to the next metric size (20 AWG,
  0.518 mm² → 0.75 mm²), so the reverse lookup maps 0.5 mm² to the
  thinner 21 AWG. A correct fix needs one table per direction and a
  rounding policy. Upstream draft #499 has not settled that policy.
  This is a product decision, not a bug fix.
- #510: `add_mate_pin` resolves pin labels the same way `connect` does.
- Tests: accept Click's `--help` hint text (8.5+) as well as `-h`.
- `setup.py`: `python_requires>=3.9`, dependency floors
  (`click>=8.0`, `pyyaml>=5.4`, `pillow>=10.3`, `graphviz>=0.20`),
  README read as UTF-8, Python 3.9-3.13 classifiers.
- CI: drop 3.7/3.8, add 3.13.

Out of scope: upstream #493 (pin labels in loops — 535-line unreviewed
draft), the `dev` refactor, jumpers, braided sleeves.

### wireviz-gui (separate repo, separate branch)

- Pass `untrusted=True` to every `parse()` call.
- Sanitize the SVG with DOMPurify (SVG profile) before `v-html`.
- Cap the request body size.

in `tests/test_regressions.py` or a new `tests/test_security.py`:

5. `fix(cli)`: CLI bug fixes.
6. `fix(render)`: dpi default, wire padding, tweak quoting, gauge.
7. `fix(mates)`: upstream #510.

   Click test text.
9. `docs`: syntax.md, CHANGELOG 0.6.0, CLAUDE.md invariants.

Then wireviz-gui on `fix/untrusted-input`.
